Productionization plan for FunPayVertex

Phase 0: Define product scope and success criteria (done)
- Document core user journeys (sign up, connect FunPay account, manage team, price items). (done)
- Define required data sources (FunPay inventory, competitor listings, sales history). (done)
- Define KPIs: price competitiveness, profit margin, time-to-update, error rate. (done)

Phase 1: Architecture and data model (done)
- Define multi-tenant schema: Account (FunPay), Organization, Team, User, Role. (done)
- Define catalog schema: Item, Listing, CompetitorListing, PriceRule, PriceHistory. (done)
- Define audit logs and data retention rules. (done)

Phase 1c: Database implementation (required) (done)
- Pick primary datastore (Postgres recommended) and define migration tooling. (done)
- Replace JSON file storage with DB-backed repositories/services. (done)
- Add indexes for core queries (inventory lookup, price history, org/team scoping). (done)
- Define backup/restore strategy and seed data for local dev. (done)

Phase 1b: Product tiers and feature gating (done)
- Define tier entitlements and feature flags for Basic, Advanced, Ultimate. (done)
- Basic (Starter) includes: Smart auto delivery 24/7 (files, multi-delivery); Auto lot bumping (cooldowns); Autoresponder with variables; Auto session recovery (Golden Key); Telegram notifications with action buttons; IPv4 proxy support; Buyer blacklist; Watermark; SRAS Monitor (hidden ban monitor); Auto Refund (rating protection); Feedback Reminder; Lot Cloner; Old Orders Scanner; Buyer Notes. (done)
- Advanced includes all Basic plus: Full sales stats (charts); Net profit calculation and payout forecast; Top Customer Analytics (LTV); Review Analytics (reputation tracker); Mass Price Editor; Copy Lots Manager (account backups); Delete Lots (profile cleanup); Word Replacer (lot text replace); Stale Lot Detector; Status Manager. (done)
- Ultimate (Team) includes all Advanced plus: Auto Dumping (auto price decrease); AutoRobux GamePass; Steam AutoPoints; Auto Send (dialog broadcasts); Auto SMM (auto promotion); AI Reviews (smart replies); Manager system (staff access); Priority support. (done)

Phase 2: Authentication and onboarding (done)
- Implement user auth (email+password, SSO optional later). (done)
- Implement organization creation and FunPay account linking. (done)
- Add invite flow for teams and managers. (done)
- Add RBAC: Owner, Admin, Manager, Analyst, Viewer. (done)

Phase 3: Team and admin controls (done)
- Build admin panel for org settings, roles, and access reviews. (done)
- Add per-team scopes for allowed categories, pricing rules, and alerts. (done)
- Add approval workflow for price changes (optional toggle). (done)

Phase 4: Data ingestion and deduping
- Build ingestion pipeline for FunPay inventory and competitor data.
- Normalize titles, attributes, and tags into canonical fields.
- Implement dedupe logic (exact match + fuzzy matching + manual merge).
- Maintain a canonical item graph to map variants and duplicates.

Phase 5: Pricing engine
- Implement pricing strategy rules (min margin, min price, undercut by X).
- Compute recommended prices using deduped canonical items and competitors.
- Add safety limits (floor/ceiling, rate limits, rollback).
- Track price effectiveness and profit impact.

Phase 6: Admin workflows and user experience
- Dashboards for inventory health, dedupe conflicts, price changes.
- Bulk actions for pricing and inventory updates.
- Notifications and alerts (price conflicts, margin risk, failures).

Phase 7: Reliability, security, and compliance
- Secrets management, encryption at rest/in transit, least-privilege access.
- Audit trails for account actions and pricing changes.
- Monitoring, logging, and incident response runbooks.

Phase 8: QA, staging, and release process
- Test suite for pricing, dedupe, and access control.
- Staging environment with seeded data.
- Release checklist and rollback procedure.

Phase 9: Payments and billing (last)
- Define pricing tiers based on teams, listings, and automation features.
- Implement subscription billing and invoice history.
- Add usage limits and upgrade/downgrade flows.
