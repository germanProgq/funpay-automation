Productionization plan for FunPayVertex

Phase 0: Define product scope and success criteria
- Document core user journeys (sign up, connect FunPay account, manage team, price items).
- Define required data sources (FunPay inventory, competitor listings, sales history).
- Define KPIs: price competitiveness, profit margin, time-to-update, error rate.

Phase 1: Architecture and data model
- Define multi-tenant schema: Account (FunPay), Organization, Team, User, Role.
- Define catalog schema: Item, Listing, CompetitorListing, PriceRule, PriceHistory.
- Define audit logs and data retention rules.

Phase 1b: Product tiers and feature gating
- Define tier entitlements and feature flags for Basic, Advanced, Ultimate.
- Basic (Starter) includes: Smart auto delivery 24/7 (files, multi-delivery); Auto lot bumping (cooldowns); Autoresponder with variables; Auto session recovery (Golden Key); Telegram notifications with action buttons; IPv4 proxy support; Buyer blacklist; Watermark; SRAS Monitor (hidden ban monitor); Auto Refund (rating protection); Feedback Reminder; Lot Cloner; Old Orders Scanner; Buyer Notes.
- Advanced includes all Basic plus: Full sales stats (charts); Net profit calculation and payout forecast; Top Customer Analytics (LTV); Review Analytics (reputation tracker); Mass Price Editor; Copy Lots Manager (account backups); Delete Lots (profile cleanup); Word Replacer (lot text replace); Stale Lot Detector; Status Manager.
- Ultimate (Team) includes all Advanced plus: Auto Dumping (auto price decrease); AutoRobux GamePass; Steam AutoPoints; Auto Send (dialog broadcasts); Auto SMM (auto promotion); AI Reviews (smart replies); Manager system (staff access); Priority support.

Phase 2: Authentication and onboarding
- Implement user auth (email+password, SSO optional later).
- Implement organization creation and FunPay account linking.
- Add invite flow for teams and managers.
- Add RBAC: Owner, Admin, Manager, Analyst, Viewer.

Phase 3: Team and admin controls
- Build admin panel for org settings, roles, and access reviews.
- Add per-team scopes for allowed categories, pricing rules, and alerts.
- Add approval workflow for price changes (optional toggle).

Phase 4: Data ingestion and deduping
- Build ingestion pipeline for FunPay inventory and competitor data.
- Normalize titles, attributes, and tags into canonical fields.
- Implement dedupe logic (exact match + fuzzy matching + manual merge).
- Maintain a canonical item graph to map variants and duplicates.

Phase 5: Pricing engine
- Implement pricing strategy rules (min margin, min price, undercut by X).
- Compute recommended prices using deduped canonical items and competitors.
- Add safety limits (floor/ceiling, rate limits, rollback).
- Track price effectiveness and profit impact.

Phase 6: Admin workflows and user experience
- Dashboards for inventory health, dedupe conflicts, price changes.
- Bulk actions for pricing and inventory updates.
- Notifications and alerts (price conflicts, margin risk, failures).

Phase 7: Reliability, security, and compliance
- Secrets management, encryption at rest/in transit, least-privilege access.
- Audit trails for account actions and pricing changes.
- Monitoring, logging, and incident response runbooks.

Phase 8: QA, staging, and release process
- Test suite for pricing, dedupe, and access control.
- Staging environment with seeded data.
- Release checklist and rollback procedure.

Phase 9: Payments and billing (last)
- Define pricing tiers based on teams, listings, and automation features.
- Implement subscription billing and invoice history.
- Add usage limits and upgrade/downgrade flows.
