Telegram integration completion plan

Goal
- Finish fpv_tg_handle_message and fpv_tg_handle_callback to match tg_bot behavior.
- Keep changes within fpv_core/src/fpv_telegram.c unless a missing helper or declaration is required.

Work items
1) Authorization and default chat notifications
- Private chat secret key check with 5 attempt limit; send access_granted/access_denied; log log_access_*.
- Ignore commands and callbacks for unauthorized users; callbacks should log log_click_attempt.
- For new chats, apply fpv_tg_setup_default_notifications unless reply_topic_created or already set.

2) Message handling core flow
- Parse slash commands and legacy reply keyboard texts.
- Support /menu, /profile, /test_lot, /upload_img, /ban, /unban, /black_list, /watermark, /logs,
  /del_logs, /about, /sys, /old_orders, /keyboard, /change_cookie, /restart, /power_off.
- Send main menu text and appropriate keyboards.

3) User state flows (FPV_TG_STATE_*)
- Add/edit auto response commands and notifications.
- Add auto delivery lot by name; edit lot delivery text; validate $product when needed.
- Bind/unbind products file; create products file; append products; upload products file.
- Send FunPay message (text and photo); edit watermark; manual ad test key.
- Ban/unban username; edit greetings, order confirm, review reply texts.
- Add template text.
- Upload main/auto_response/auto_delivery configs; upload image.
- Clear state should delete prompt message when requested.

4) File and image handling
- Validate uploaded file name, size <= 20MB, ext in .cfg/.txt/.py.
- Download via getFile and save with fpv_tg_write_file_data.
- For products files, ensure .txt; count goods after upload.
- For photos, download from Telegram and upload to FunPay; return image id.

5) Auto response config operations
- Use fpv_ini to add/edit/delete commands.
- Keep telegramNotification sync for command sets split by '|'.
- Reload with fpv_features_reload_auto_response.

6) Auto delivery config operations
- Use fpv_ini to add/edit/delete lots, toggle disable flags, bind products file.
- Create goods file if missing; enforce $product for linked goods file.
- Test key generation stored in service->delivery_tests with mutex.
- Reload with fpv_features_reload_auto_delivery.
- Update lot list from FunPay via fpv_tg_update_profile_lots.

7) Templates and messaging
- Add/edit/delete/list templates; save to cache via fpv_tg_save_answer_templates.
- Send template into FunPay chat using fpv_features_send_message and username substitution.

8) Notifications and settings callbacks
- Implement callback switchers:
  - fpv_tg_cbt_switch for main settings (update ini, reload, refresh keyboard)
  - fpv_tg_cbt_switch_tg for per-chat notification toggles
- Implement category navigation (main, tg, ar, ad, bl, gr, oc, rr, mv, configs, templates).
- Implement language switch callback (fpv_tg_cbt_lang).

9) Order and message actions
- Refund flow: request, confirm with retries, cancel, update keyboards.
- Reply flow: send FP message, back to reply/order, extend chat history.

10) Profile, logs, and system commands
- /profile and update_profile callbacks refresh account and show profile.
- /old_orders uses get_orders_page with state=paid and age > 24h.
- /logs sends latest log file; /del_logs deletes old logs safely.
- /sys shows CPU/RAM/uptime; /about shows version.

11) Power control and misc callbacks
- /restart uses restart_fn; /power_off uses staged keyboard and shutdown_fn.
- Handle fpv_tg_cbt_param_disabled, fpv_tg_cbt_old_help, fpv_tg_cbt_empty, fpv_tg_cbt_clear_state.

Non-goals
- UI/app changes or new dependencies.
- Additional localization keys unless required by missing text.

Suggested implementation order
- Implement fpv_tg_handle_message (authorization + commands + state handling).
- Implement fpv_tg_handle_callback (navigation + toggles + edits + actions).
- Add any missing helpers inside fpv_telegram.c only if necessary.
- Update plan.txt Phase 5 and tool plan after code completion.
